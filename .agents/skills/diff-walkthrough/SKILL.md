# Diff Walkthrough

Walk the user through the repository's unstaged changes one small piece at a time. Explain what changed and what it does. Stop after each piece and wait for the user's questions or feedback before continuing.

The user is an expert programmer conducting a code review while learning Go. Explain Go-specific syntax or conventions only when they are needed to understand the code.

Do not plan or announce the whole walkthrough in advance. Do not stage or commit anything unless the user asks.
